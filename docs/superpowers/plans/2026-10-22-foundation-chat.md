# Foundation + Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Tab5 runs our trimmed Clientre5 fork. You type a question on the A164 keyboard and Claude's answer streams onto the screen.

**Architecture:** Keep Clientre5's hardware platform and delete its SSH, terminal, IME and Tailscale stack. Add `components/claude_api`: pure SSE, request and error code that is unit-tested on the Mac, plus a thin `esp_http_client` transport. Add a chat screen in `main/ui/`. A USB serial console provides screenshots, API-key provisioning and an `ask` command, so every step can be checked from the Mac.

**Tech Stack:** C, ESP-IDF v5.5.6 (target `esp32p4`), LVGL 9.4 + esp_lvgl_port 2.8, cJSON (IDF `json` component), `esp_http_client` + `esp-x509-crt-bundle`, `esp_console`, `esp_driver_jpeg`, Unity for host tests, Python 3 + pyserial for host tools.

**Spec:** `docs/superpowers/specs/2026-10-22-claude-tab5-design.md`

## Global Constraints

- Build: `. ~/esp/esp-idf/export.sh && cd firmware && idf.py set-target esp32p4 && idf.py build` (ESP-IDF v5.5.6).
- Dev flashing: `idf.py -p /dev/cu.usbmodem211201 flash`, logs with `idf.py -p /dev/cu.usbmodem211201 monitor` (exit with `Ctrl+]`). Find the port with `ls /dev/cu.usbmodem*`.
- Every task runs in its own git worktree off `main` and merges back when its tests pass (user rule). The top-level checkout stays on `main`.
- Match Clientre5's C style: 4-space indent, function opening brace on its own line, `static const char *TAG = "...";`, `s_` prefix for file-scope statics, `/* */` comments.
- `claude_sse.c`, `claude_request.c`, `claude_util.c` and `chat_model.c` include no ESP-IDF headers. They also build in `firmware/test/host`.
- Host tests: `cmake -S firmware/test/host -B firmware/test/host/build && cmake --build firmware/test/host/build && ctest --test-dir firmware/test/host/build --output-on-failure`.
- Claude API values in the spec's "Claude API rules" section are binding: endpoint, `anthropic-version: 2026-10-21`, `anthropic-beta: server-side-fallback-2026-07-01`, model `claude-opus-5-5`, `stream: true`, `fallbacks: "default"`, `output_config.effort: "low"`, `max_tokens: 8192`. Never send `temperature`, `top_p`, `top_k`, `thinking` or an assistant prefill.
- API key: never committed, never logged beyond the last 4 characters, and never placed in `ANTHROPIC_API_KEY`.
- After Task 3 there is no GPL or LGPL code in `firmware/`. Keep `firmware/LICENSE.clientre5`.
- UI colors come only from the spec's D7 table. Amber (`#f4b545`) means "needs you" and nothing else.
- Check every visible UI change with `python3 firmware/tools/screenshot.py` and look at the saved image.

## Review Focus

1. SSE data split across reads, including in the middle of a multi-byte UTF-8 character → the text comes out intact. Covered by Task 5 `test_sse_utf8_split_bytewise`.
2. Wi-Fi drops or the server stalls mid-reply → an error appears within 30 s and the input works again. Covered by Task 6's device check and Task 7 `test_failed_exchange_excluded`.
3. HTTP 401, 429, 529 and 400 → a readable one-line message, never raw JSON. Covered by Task 5 `test_error_event_parsed` and Task 6 `test_http_error_text_mapping`.
4. `stop_reason` of `refusal` or `max_tokens` → an explicit note under the reply. Covered by Task 5 `test_message_delta_stop_reason` and Task 7 `test_stop_note`.
5. Long conversations → history is capped at 64 KB, the oldest exchanges are dropped, and PSRAM is never exhausted. Covered by Task 7 `test_history_trims_oldest`.

```c
typedef enum {
    CLAUDE_EV_TEXT,      /* text delta: text, len */
    CLAUDE_EV_THINKING,  /* a thinking block started (drives the "Thinking…" indicator) */
    CLAUDE_EV_RESET,     /* server-side fallback: discard reply text received so far */
    CLAUDE_EV_STOP,      /* message_stop: stop_reason from the preceding message_delta */
    CLAUDE_EV_ERROR,     /* error_type, message */
} claude_ev_kind_t;

typedef struct {
    claude_ev_kind_t kind;
    const char *text;          /* CLAUDE_EV_TEXT, not NUL-terminated */
    size_t len;
    const char *stop_reason;   /* CLAUDE_EV_STOP: "end_turn", "max_tokens", "refusal", ... */
    const char *error_type;    /* CLAUDE_EV_ERROR, e.g. "overloaded_error" */
    const char *message;       /* CLAUDE_EV_ERROR, human-readable */
} claude_ev_t;

typedef void (*claude_ev_cb_t)(const claude_ev_t *ev, void *ctx);

typedef struct claude_sse claude_sse_t;
claude_sse_t *claude_sse_new(claude_ev_cb_t cb, void *ctx);   /* lines up to 64 KB */
void claude_sse_feed(claude_sse_t *p, const char *data, size_t len);
bool claude_sse_saw_stop(const claude_sse_t *p);
void claude_sse_free(claude_sse_t *p);
```

- Produces, in `claude_request.h`:

```c
typedef struct { const char *role; const char *text; } claude_turn_t;   /* role: "user" | "assistant" */
typedef struct { const char *model; int max_tokens; const char *effort; const char *system; } claude_req_opts_t;
char *claude_request_json(const claude_req_opts_t *opts, const claude_turn_t *turns, size_t n);
/* malloc'd; the caller frees it. Returns NULL for an empty list, a role other than user/assistant,
   or a first turn that isn't "user". */
```

Event handling: dispatch on a blank line. `ping`, `message_start`, `content_block_stop` and unknown events produce no callback. A `content_block_start` of type `thinking` produces one `CLAUDE_EV_THINKING`. `thinking_delta` and `signature_delta` produce nothing. Each `fallback` event produces one `CLAUDE_EV_RESET`.

```c
typedef struct chat_model chat_model_t;

void chat_model_add_user(chat_model_t *m, const char *text);
void chat_model_begin_assistant(chat_model_t *m);

/* the request history: completed exchanges only, oldest first, total text ≤ max_bytes, always starting with "user" */
size_t chat_model_count(const chat_model_t *m);                  /* displayed entries, failed ones included */
const char *chat_model_text(const chat_model_t *m, size_t idx);
bool chat_model_is_user(const chat_model_t *m, size_t idx);
const char *chat_model_note(const chat_model_t *m, size_t idx);
/* "Reply cut off at the length limit." | "Claude declined this request." | "Stopped." | the error text | NULL */

```

- Screen layout:
  - Top: a vitals bar with battery % (plus `charging` when charging), Wi-Fi state and the clock (`HH:MM`).
  - Middle: a scrolling transcript. User entries are right-aligned on panel-2; Claude's replies are left-aligned in fg.
  - Bottom: an input line with the placeholder `Ask Claude…` and an amber cursor.
- Notes: shown in muted under the reply. Errors are shown in red.
- Keys:
  - Enter sends; it is ignored while a reply is streaming.
  - Esc cancels the reply in flight, otherwise it clears the input.
  - ↑ recalls the last prompt.
  - Ctrl+L starts a new conversation.
- States:
  - `Thinking…` in muted from send until the first text, and on `CLAUDE_EV_THINKING`.
  - No key: input disabled, with the message `Add your API key: run firmware/tools/provision_key.py on your computer.`
  - No Wi-Fi: `Not connected to Wi-Fi. Open Wi-Fi to connect.`
- Updating: the client task hands deltas to LVGL under `lvgl_port_lock`, at most every 50 ms.
